## 目的・背景

Neovim のプラグインからリンク先のノートへジャンプできるようにする。プラグインは CLI をサブプロセスで呼ぶので、リンク 1 つを解決する入口が要る。解決の規則は links（2026-10-25_links.md）で作った `Links::Resolver` をそのまま使う。

仕様は 2026-10-25 に grilling で合意した（Q1〜Q10）。

スコープ外:
- 見出しとブロック参照へのジャンプ（`#` 以降は捨てる）
- Lua のプラグイン本体。どのリンクを渡すか（カーソル位置の扱い）はプラグイン側の責務

feature/links（PR #12）の上に積む。

## 仕様

```
nob resolve <link> [--from <path>]
```

### `<link>`

- 前後の空白を除いた引数が、`Links.extract` で取り出したリンク 1 件の `raw` と完全に一致するときだけ受け付ける
- それ以外は `Error: expected a single [[link]]: <arg>` / exit 1
  - 括弧なし（`Plan`）、前後に文字がある（`see [[Plan]] here`）、2 件（`[[a]] [[b]]`）、名前が空（`[[#見出し]]`）、インラインコード

### `--from <path>`

- 絶対パスも相対パスも受け付ける。相対パスは vault を基準にする（`./` 付きも同じ）
- 絶対パスはまず字句的に vault の中か判定し、外なら vault の `realpath` を基準にもう一度判定する（symlink 経由の vault）
- 距離の起点はそのファイルのディレクトリ
  - 存在しない: そのまま起点にする（保存前のバッファ）
  - ディレクトリ: `Error: --from is not a file: <path>` / exit 1
  - vault の外: `Error: --from is outside the vault: <path>` / exit 1
  - 存在するファイル: 種類を問わない
- 省略したら vault 直下のノートから書いたものとして測る

### 出力

判定できれば結果によらず exit 0。結果は stdout の行数で区別する。

| 結果 | stdout |
|---|---|
| 解決 | 絶対パスを 1 行 |
| 曖昧 | 候補の絶対パスを 1 行に 1 件（パス順。必ず 2 行以上） |
| 未解決 | 空 |

## 設計

```ruby
# lib/nob/links.rb
Nob::Links.parse(text)  # -> Link | nil  text がちょうど 1 つのリンクなら Link。純粋関数

# lib/nob/vault.rb
Nob::Vault.relative_path(vault, path)  # -> String  vault 相対パス。外なら InvalidPath
```

- `Links.parse` は `extract` の結果が 1 件で、その `raw` が `text.strip` と一致するときだけ Link を返す
- `Vault.relative_path` は相対パスを vault 基準で `File.expand_path` し、vault の中か判定する。絶対パスで外だった場合は `File.realpath(vault)` を基準にもう一度判定する。`path` 自体の realpath は取らない（存在しないことがある）
- 絶対パスへの変換は CLI が `File.join(vault, rel)` で行う（出力は `create` の `Created:` と同じ組み立て方）
- 例外を `Error:` にするのは今までどおり CLI

## 実装と計画の差分（recap）

- `Vault.relative_path` の外判定の文言は `path is outside the vault: <path>`。CLI が `normalize_prefix` と同じやり方で `path ` を `--from ` に置き換える
- `--from` を省いたときの起点は `"."`（`Resolver#distance` で vault 直下として扱われる）
- `--from` に vault のルート（`.`）を渡すと、ディレクトリなので `--from is not a file` になる
- 出力の絶対パスは config の vault（`~` は展開済み、symlink は追わない）に vault 相対パスを足したもの。realpath の `--from` を渡しても、出力は symlink 側のパスになる
- T2: symlink の再判定を外すと spec が 1 件落ちることを確かめた
- 手動確認: symlink 経由の一時 vault で、解決・曖昧（2 行）・未解決（空）がどれも exit 0、括弧なしとディレクトリの `--from` が exit 1、実体側の絶対パスの `--from` で最も近い候補が選ばれる
- レビュー対応: R3 と R4 は spec が同じ describe に入るので、1 つのコミットにまとめた
- R1: `LANG=C` の再現は、spec の中で `Encoding.default_external` を US-ASCII に変えて確かめた。`Vault.frontmatter` は `parse_file` をやめ、`Vault.read` で読んだ文字列を解析する
- R4: vault 内の symlink のディレクトリ（`today -> daily`）は字句的な判定で先に通るので、`today/x.md` のまま返す（実体のパスに直さない）
- R8: レビューは「`Dir.glob` のファイル名が ASCII-8BIT になる」とも指摘したが、`Dir.glob` は base と同じエンコーディングで返すので、vault のファイル名は UTF-8 のままだった。落ちるのは ARGV と、不正なファイル名の 2 経路だった
- R14: `Hash.new` の default proc は表を作るときだけ使い、引くときは `fetch(key, [])` にして、存在しない鍵で表が増えないようにした
