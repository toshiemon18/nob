## 目的・背景

Neovim プラグイン（2026-10-26 の grilling、Q1〜Q25）に着手する前に、CLI の応答時間を縮める。プラグインは nob を同期的に呼ぶので、リンクへのジャンプに数秒かかると使えない。

実際の vault（`.md` 457 件、ファイル 467 件、ディレクトリ 59）を WSL から `/mnt/c` 越しに使って測った（5 回の中央値）。

| コマンド | `/mnt/c` | ext4 にコピー |
|---|---|---|
| `nob version` | 233 ms | ― |
| `nob list` | 1,669 ms | 244 ms |
| `nob resolve` | 1,771 ms | 267 ms |
| `nob show` | 3,218 ms | 257 ms |
| `nob links --unresolved` | 3,293 ms | 310 ms |

- 遅いのは、`Vault.list` と `Vault.files` がファイルごとに `File.file?`（stat）を呼ぶこと。9P 越しだとこれだけで約 1.4 秒かかる
- `Dir.glob("**/*")` から `Dir.glob("**/*/")` を引けば、stat なしで同じ 467 件が取れる（1,590 ms → 361 ms）。glob はディレクトリの判定に readdir の d_type を使う
- `show` は `find_notes`（`list`）と `Resolver` 用の `files` で 2 回走査している。resolve のレビュー（2026-10-26）では「個人の vault では差が出ない」として見送ったが、`/mnt/c` では時間がほぼ 2 倍になる
- `bundle exec` は起動に約 100 ms 上乗せする（`ruby -Ilib` だと 132 ms）

目標は、WSL ＋ `/mnt/c` で `list` / `resolve` / `show` / `links` がそれぞれ約 0.5 秒以内に収まること。

スコープ外:
- 走査結果のキャッシュ（状態を持たない方針を変えない）
- 非同期化（プラグイン側の話）

## 設計

- `Vault.files` と `Vault.list` は、`Dir.glob(pattern)` から `Dir.glob("#{pattern}/")`（ディレクトリだけ）を引いて、ファイルを取り出す。ファイルごとの stat はしない
- `Vault.find_notes(vault, title, notes = list(vault))` とし、走査済みの一覧を渡せるようにする（`Vault.frontmatter(path, text = read(path))` と同じ形）
- `nob show` は `Vault.files` を 1 回だけ呼び、`.md` に絞ったものを `find_notes` に、全体を `Resolver` に渡す（`nob links` と同じ）
- README に、普段は `gem install` した nob を bundler なしで起動することを書く

### symlink

| エントリ | 今 | glob の差分 |
|---|---|---|
| ファイルへの symlink | 含む | 含む |
| ディレクトリへの symlink | 含まない（中も辿らない） | 含まない（中も辿らない） |
| リンク先のない symlink | 含まない | **含む** |

リンク先のない symlink だけ振る舞いが変わる。stat せずには見分けられないので、受け入れる。`nob links` がそれを読むと `Errno::ENOENT` になるが、Dropbox などで同期する Obsidian の vault に symlink を置くことはまずない。ADR 0002 の「ファイルシステムの異常は素通し」の範囲として扱う。

### テストする seam

| seam | 捕まえるもの |
|------|-------------|
| S1: `Nob::Vault.files` / `.list` | 既存の振る舞い（ディレクトリ、`.md` で終わるディレクトリ、隠しファイル、prefix）と symlink の扱い |
| S2: `Nob::Vault.find_notes` | 渡した一覧から探す |
| S3: `Nob::Cli.start(["show", ...])` | 既存の出力のまま |

## 結果

同じ vault を `/mnt/c` 越しに測った（5 回の中央値）。

| コマンド | 変更前（`bundle exec`） | 変更後（`bundle exec`） | 変更後（bundler なし） |
|---|---|---|---|
| `nob list` | 1,669 ms | 576 ms | 481 ms |
| `nob resolve` | 1,771 ms | 612 ms | 497 ms |
| `nob show` | 3,218 ms | 625 ms | 510 ms |
| `nob links --unresolved` | 3,293 ms | 2,243 ms | 2,133 ms |

- `list` / `resolve` / `show` は目標の約 0.5 秒に収まった
- `links --unresolved` は、残りの大半が全ノート（457 件）を 9P 越しに読む時間（1 件あたり約 3.5 ms）。最初のマイルストーンではプラグインから呼ばないので、ここでは直さない。quickfix 連携を作るときに、読み込みの並列化か非同期化を考える
