## 目的・背景

Obsidian のデイリーノート機能と nob で、同じテンプレートを使えるようにする。Neovim プラグイン（2026-10-26 の grilling、Q9・Q12〜Q14）で dotfiles の `daily_notes` を置き換える前提になる。

実際の vault では、テンプレートも Obsidian の設定も moment 形式（moment.js の書式）で書いている。

```
# templates/daily_node_template.md
created: {{date:YYYY-MM-DD}}T{{time:HH:mm}} (UTC +09:00)

# .obsidian/daily-notes.json
"format": "YYYY/MM/YYYY-MM-DD"
```

今の nob は書式をすべて strftime として扱うので、このテンプレートを読むと、エラーにならずに `YYYY-MM-DD` という文字列がそのまま書き込まれる。

スコープ外:
- `.obsidian/daily-notes.json` を読んで設定の既定値にすること（Obsidian の内部ファイルに依存するため。Q13）
- moment の全トークン。よく使うものだけに絞る

PR #16（feature/perf）の上に積む。

## 仕様

### どちらの形式として読むか

- 書式に `%` を含めば strftime、含まなければ moment として読む
- `{{date:timestamp}}` と `{{time:timestamp}}` は今までどおり unixtime

### moment 形式

| トークン | 意味 | 例（2026-03-07 09:05:02） |
|---|---|---|
| `YYYY` | 西暦 4 桁 | `2026` |
| `YY` | 西暦の下 2 桁 | `26` |
| `MM` / `M` | 月（2 桁 / ゼロ埋めなし） | `03` / `3` |
| `DD` / `D` | 日（2 桁 / ゼロ埋めなし） | `07` / `7` |
| `HH` / `H` | 時（24 時間制。2 桁 / ゼロ埋めなし） | `09` / `9` |
| `mm` | 分（2 桁） | `05` |
| `ss` | 秒（2 桁） | `02` |

- 英字は同じ文字の連なりごとに区切り、それぞれが表のトークンちょうどのときだけ受け付ける。`YYYYMMDD` は `YYYY` `MM` `DD`。`MMMM`（moment では月名）や `MMM` を `MM` と `M` の並びとは読まない
- `[...]` の中は文字どおりに出力する（moment のエスケープと同じ）。閉じの `]` がなければエラー
- 英字（`A-Z` `a-z`）以外の文字はそのまま出力する。`年` や `/` など
- 上の表にない英字の並び（`dddd`、`Do`、`m` など）はエラーにする。黙って文字どおりに出すと、今回の問題と同じことが起きるため

### エラー

| 場所 | 出力 |
|---|---|
| テンプレート | `Error: unsupported format token: dddd: {{date:dddd}} (line 3)` |
| `[dailyNote].fileNameFormat` | `Error: unsupported format token: dddd ([dailyNote].fileNameFormat)` |

テンプレートの場合は、今の未定義変数と同じく、Parser の段階でエラーにする（ADR 0001 の「構文エラーと未定義変数は Parser で全部検出する」）。

### デイリーノートの `{{title}}`

`fileNameFormat` から作った名前の basename にする。`YYYY/MM/YYYY-MM-DD` なら、ファイルは `daily/2026/10/2026-10-27.md`、`{{title}}` は `2026-10-27`。今は `2026/10/2026-10-27` になる。

## 設計

```ruby
# lib/nob/time_format.rb
Nob::TimeFormat.new(fmt)   # moment なら strftime の書式に変換する。対応しないトークンは UnsupportedToken
Nob::TimeFormat#format(time)  # -> String
Nob::TimeFormat::UnsupportedToken < Nob::Error
```

- moment の書式は、生成時に strftime の書式に変換しておく（`YYYY` → `%Y`、`M` → `%-m`）。moment として読むのは `%` を含まない書式なので、リテラルはそのまま入れてよい。検証も生成時に終わるので、テンプレートでは Parser の段階でエラーになる
- テンプレートとデイリーノートのファイル名の両方で使うので、`Templates` の外に置く
- `Operators::Date` と `Operators::Time` は、生成時に `TimeFormat` を作る。`UnsupportedToken` は `UndefinedVariable` にする（Parser が変数と行番号を付ける）
- `nob daily` は `UnsupportedToken` に `([dailyNote].fileNameFormat)` を付けて `Nob::Error` にする（`Templates.locate` が指定元を付けるのと同じ形）

### テストする seam

| seam | 捕まえるもの |
|------|-------------|
| S1: `Nob::TimeFormat` | 形式の判定、各トークン、最長一致、`[...]`、英字以外、対応しない英字、閉じない `[` |
| S2: `Operators::Date` / `Time` と `Templates.render` | moment の書式、エラーに変数と行番号が付くこと |
| S3: `Nob::Cli.start(["daily"])` | moment の fileNameFormat で作るパス、`{{title}}`、エラーの文言 |

## 結果

実際の vault のテンプレートを（書き込まずに）展開して確かめた。

- `templates/daily_node_template.md` は `created: 2026-10-27T00:33 (UTC +09:00)` と `# 2026-10-27` に展開された
- Obsidian の fileNameFormat（`YYYY/MM/YYYY-MM-DD`）からは `2026/10/2026-10-27` ができた
- vault にある他の 3 つのテンプレートも、エラーにならずに展開できた
